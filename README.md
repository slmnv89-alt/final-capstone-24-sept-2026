Прогноз низкой оценки клиента для Olist
О проекте
В этом проекте я работал с открытым датасетом бразильского маркетплейса Olist.
Цель проекта — попробовать предсказать, поставит ли клиент низкую оценку заказу (1–2 звезды), еще до того, как он оставит отзыв.
Для прогноза использовались данные, которые известны к моменту доставки заказа: сроки доставки, стоимость заказа, стоимость доставки, способ оплаты, категория товара, информация о продавце и клиенте.
Данные
Использовался датасет Olist с Kaggle:
https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce
В датасете 9 связанных CSV-файлов:
	•	orders
	•	order_items
	•	payments
	•	reviews
	•	customers
	•	products
	•	sellers
	•	geolocation
	•	product_category_name_translation
Все таблицы были загружены в SQLite.
SQL
Сначала я проверил количество строк и уникальных order_id.
Так как в order_items, payments и reviews один заказ может встречаться несколько раз, эти таблицы нельзя было просто соединить через JOIN.
Поэтому сначала были сделаны агрегации до уровня заказа.
Например, для товаров были рассчитаны:
	•	количество товаров в заказе;
	•	количество уникальных товаров;
	•	количество продавцов;
	•	общая стоимость товаров;
	•	общая стоимость доставки.
После этого таблицы были объединены через SQL JOIN.
Для заказов с несколькими товарами в качестве основного товара использовался самый дорогой товар.
В финальной таблице одна строка соответствует одному заказу.
Итоговый датасет:
	•	95 832 заказа;
	•	24 колонки;
	•	0 дубликатов по order_id.
Целевая переменная
Из оценки review_score была создана бинарная переменная low_review:
	•	1 — если оценка 1–2 звезды;
	•	0 — если оценка 3–5 звезд.
Низкие оценки составляют около 12.8% всех заказов, поэтому классы несбалансированы.
EDA
Во время анализа данных я рассмотрел несколько вопросов.
1. Распределение низких оценок
Около 12.8% заказов получили оценку 1–2 звезды.
2. Связь сроков доставки и низких оценок
У заказов, доставленных вовремя, доля низких оценок составила около 9.2%.
У опоздавших заказов доля низких оценок была около 54%.
Также заказы с низкими оценками в среднем доставлялись дольше.
3. Стоимость заказа и доставки
У заказов с низкими оценками медианная стоимость заказа и доставки была немного выше.
4. Категории товаров
Для некоторых категорий товаров доля низких оценок была выше средней.
Например, среди категорий минимум со 100 заказами выделялись:
	•	fashion_male_clothing;
	•	office_furniture;
	•	audio.
Подготовка данных для ML
Для модели была создана отдельная таблица df_ml.
Из нее были удалены:
	•	order_id;
	•	review_score, потому что из него была создана целевая переменная;
	•	сырые даты;
	•	ID товаров и продавцов;
	•	город клиента.
Данные были разделены на train и test в пропорции 80/20.
Использовался stratify=y, чтобы доля низких оценок была примерно одинаковой в train и test.
Для числовых признаков:
	•	пропуски заполнялись медианой;
	•	использовался StandardScaler.
Для категориальных признаков:
	•	пропуски заполнялись самым частым значением;
	•	использовался One-Hot Encoding.
Вся обработка была сделана через Pipeline.
Модели
Были обучены две модели:
	•	Logistic Regression;
	•	Random Forest.
Так как классы несбалансированы, использовался class_weight='balanced'.
Результаты
Logistic Regression
	•	Precision: 0.355
	•	Recall: 0.547
	•	F1-score: 0.431
	•	ROC-AUC: 0.755
Random Forest
	•	Precision: 0.713
	•	Recall: 0.296
	•	F1-score: 0.419
	•	ROC-AUC: 0.746
Logistic Regression нашла больше заказов, которые действительно получили низкую оценку, то есть у нее выше Recall.
Random Forest реже отмечала заказ как проблемный, но если отмечала, то чаще оказывалась права, поэтому у нее выше Precision.
Для данной бизнес-задачи Recall важен, потому что цель — заранее найти как можно больше потенциально недовольных клиентов.
Важность признаков
По Random Forest самыми важными признаками оказались:
	•	delay_days;
	•	delivery_days;
	•	total_payment_value;
	•	total_freight;
	•	total_price;
	•	is_late.
Это совпадает с результатами EDA: сроки доставки сильно связаны с низкой оценкой.
Итог
По результатам проекта сроки доставки оказались одним из самых важных факторов для прогноза низкой оценки.
Такую модель можно использовать как дополнительный инструмент для поиска заказов с повышенным риском плохого отзыва.
Например, для таких заказов можно заранее:
	•	связаться с клиентом;
	•	проверить проблему с доставкой;
	•	подключить поддержку;
	•	предложить компенсацию.
Ограничения
	•	Используются исторические данные Olist.
	•	Для заказа с несколькими товарами в качестве основного использовался самый дорогой товар.
	•	Текст отзывов не использовался.
	•	Модель использует данные, известные к моменту фактической доставки.
